Google Drive setup guide

Private client files are stored in the connected Google account. Each client gets one folder. Portal uploads, dashboard uploads, and downloads all use that folder.

1. What this connects

  • The same Google account already used for Jethro’s calendar (Book a call / check-ins).
  • A parent folder named Blocharch Clients.
  • One folder inside it per private client, named from the client record.
  • Files added in Drive itself show on the client portal. Files marked hidden in the dashboard stay in the folder but do not appear on the portal.

Blocharch Clients / {client name} /

2. Google Cloud

  1. Open Google Cloud Console and select the Blocharch project (or create one).
  2. Go to APIs & Services → Library.
  3. Enable Google Drive API. Leave Google Calendar API enabled as well.
  4. Open OAuth consent screen.
  5. Add these scopes:
    • https://www.googleapis.com/auth/calendar
    • https://www.googleapis.com/auth/calendar.events
    • https://www.googleapis.com/auth/drive
  6. If the app is in Testing, add the Google account you will sign in with as a test user.
An existing calendar refresh token does not include Drive. You must sign in again after adding the Drive scope.

3. OAuth client

  1. APIs & Services → Credentials → Create credentials → OAuth client ID.
  2. Application type: Web application.
  3. Authorized redirect URI — use the live site, not localhost:
    • https://dashboard.blocharch.com/api/google/oauth/callback
    • https://blocharch.vercel.app/api/google/oauth/callback if you open the console on that host
  4. Copy the Client ID and Client secret into the site environment and redeploy before the next step.

4. Refresh token

On the machine you are using, log in to the console as an admin, then open:

https://dashboard.blocharch.com/api/google/oauth/start
  1. Google sends you back to the site callback. Stay logged in to Blocharch in that browser.
  2. Sign in as the Google account that should own the client folders.
  3. Approve Calendar and Drive.
  4. The site shows GOOGLE_REFRESH_TOKEN. Copy it into the site environment and redeploy. Use the refresh token, not a short-lived access token.
This works over remote desktop because the callback is on the website. Nothing has to listen on localhost.

5. Environment variables

Add these to local .env.local and to the Vercel project for dashboard.blocharch.com (Production). Redeploy after saving them on Vercel.

GOOGLE_CLIENT_ID=....apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-...
GOOGLE_REFRESH_TOKEN=1//0g...
GOOGLE_DRIVE_ROOT_FOLDER_ID=
VariableRequiredWhat it does
GOOGLE_CLIENT_IDYesOAuth client
GOOGLE_CLIENT_SECRETYesOAuth client
GOOGLE_REFRESH_TOKENYesAccess for Calendar and Drive. Must be issued after the Drive scope was added.
GOOGLE_DRIVE_ROOT_FOLDER_IDNoUse an existing parent folder. Leave empty to create “Blocharch Clients” in that account’s Drive.
GOOGLE_CALENDAR_IDNoCalendar only. Default primary.
Do not commit these values. If a refresh token is exposed, open /api/google/oauth/start again and replace it.

6. How files move

  • Dashboard → Private project → Documents. Upload a PDF, image, Word, or Excel file (up to 50 MB). It is saved in that client’s Drive folder. It stays off the portal until “show on client portal” is checked.
  • Client portal → Actions. The client can drop a file. It is saved in the same folder and is visible on the portal.
  • Drive itself. Anything placed directly in the client folder appears on the portal the next time the project or portal is opened. Removing a file from Drive removes it from the portal list.
  • Downloads and previews are read from Drive. They are not stored as public website files.

Until the three required variables are set, dashboard uploads stay on the server and the portal upload tells you Drive is not connected.

7. Check that it works

  1. Restart the app locally, or wait for the Vercel deploy.
  2. Open a private project in the dashboard and upload a small PDF with “show on client portal” checked.
  3. In Google Drive, confirm Blocharch Clients / {client name} contains that file.
  4. Open the client portal (/private/{slug}) and confirm the file is under Documents and can be downloaded.
  5. Drop a second file into that Drive folder, refresh the portal, and confirm it appears.
  6. Uncheck the portal flag on the dashboard file, refresh the portal, and confirm that file is hidden. It should still be in Drive.

8. If something fails

  • Insufficient permissions / access denied. The refresh token was created before Drive was added. Open /api/google/oauth/start again and replace GOOGLE_REFRESH_TOKEN.
  • Google Drive is not connected. One of the three required variables is missing in the environment that is actually running (local vs Vercel).
  • Upload works locally and fails on the live site. The Vercel project does not have the variables, or Production was not redeployed after they were added.
  • Redirect URI mismatch. The host in the browser must match a redirect URI on the OAuth client, for example https://dashboard.blocharch.com/api/google/oauth/callback.
  • Wrong Drive account. When Google asks you to sign in, use the account that should own the client folders.
